Intelligent SOC: WAF, SIEM & Threat Intelligence

Academic project (PFA) carried out at DXC Technology, Rabat, 2025 to 2026. Active.

Three segmented networks behind pfSense: Kali attacks OWASP Juice Shop through an Nginx WAF with ModSecurity v3 and the OWASP CRS, while Suricata 8 and Zeek watch the same traffic. Universal Forwarders ship the logs to Splunk, which correlates WAF and IDS events into one incident alert, mapped to MITRE ATT&CK on a Dashboard Studio dashboard. When an alert fires, n8n sends it to an AI agent (Claude API) and adds its short description and suggested action to the dashboard; it is advisory only, the analyst decides. n8n also proposes new rows for the ATT&CK mapping, which I approve one by one, and regenerates the Navigator layer.

  • Splunk Enterprise
  • ModSecurity v3
  • OWASP Core Rule Set
  • Suricata 8
  • Zeek
  • pfSense
  • n8n
  • Claude API
  • MITRE ATT&CK
  • T1190

Multi-Site Palo Alto NGFW & Route-Based IPsec VPN (EVE-NG)

Academic project, 2025 to 2026.

Two sites joined by an encrypted tunnel across a simulated ISP, each behind a Palo Alto VM-Series firewall.

Supervised by Mme Chaimae Kissi.

  • Two sites connected over a simulated public ISP backbone (Cisco 7206VXR as the ISP core), each protected by a Palo Alto VM-Series NGFW, built in EVE-NG with management through the Cloud0 bridge.
  • Route-based site-to-site IPsec VPN using tunnel interfaces (tunnel.1, zone VPN): IKEv2, AES-256, SHA-256.
  • Zone-based security with Trust, Untrust and VPN zones and granular least-privilege permit rules for cross-site traffic.
  • Interface Management Profiles limiting HTTPS, SSH and Ping to specific interfaces, protecting the control plane.
  • Virtual router separating underlay (ISP reachability) from overlay (tunnel) routing; static and default routes force internal traffic through the encryption engine.
  • LAN 1 10.1.1.0/24 to LAN 2 20.1.1.0/24 across the tunnel.
  • Palo Alto NGFW
  • IPsec/IKEv2
  • EVE-NG
  • Zero Trust zones

Hospital City Network Design (Cisco Packet Tracer)

Academic team project.

One secure, redundant network for a medical city of four hospitals, designed for a Ministry of Health scenario.

Team of four, supervised by Mme Kissi. A national health plan funds a medical city with four hospitals (General, 582 beds; Maternity & Children, 347; High-Security Forensic Psychiatry, 100; Physiotherapy & Rehabilitation, 150), and the Ministry of Health needs one secure network across all sites.

  • Hierarchical, redundant design: each site has a core router, two multilayer (L3) switches and access switches per department; HQ and branch linked over serial WAN; dual ISP with a main default route and a floating backup static route.
  • One VLAN and subnet per department with VLSM: /25 for departments of about 100 hosts, /27 for about 25, /28 for the server segment, /30 for point-to-point links.
  • OSPF (area 0) on routers and L3 switches, inter-VLAN routing on the L3 switches, DHCP servers in the server room with ip helper-address, static IPs for servers.
  • SSH only on routers and L3 switches (RSA keys, local login, transport input ssh), service password-encryption and banners.
  • Port security on the server-department switch: sticky MAC, one device maximum, shutdown on violation.
  • Site-to-site IPsec VPN with an extended ACL between HQ and branch; PAT and ACLs on the edge routers.
  • A Cisco ASA firewall between locations with security levels (trusted 100, untrusted 50), static routes, ACLs and ICMP inspection.
  • A wireless network per department.
  • Second part: a healthcare-segment design (private ward, general ward, clinical area, IT department, entrance reception, lobby, parking and cafeteria) with VLSM and DHCP, DNS, HTTP(S), SMTP, FTP and Wi-Fi services.
  • OSPF
  • VLANs
  • IPsec VPN
  • Cisco ASA
  • Port security
  • PAT
